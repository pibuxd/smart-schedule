# CLAUDE.md

Grafikomat: web app for building work schedules for shift-based venues (bakeries, cafés, restaurants, hotels).
Scope and requirements: `docs/spec.md`. Technical plan, data model, endpoints, stages: `docs/plan.md`.

## Working rules

- Talk to Piotr in Polish. Code, identifiers and commit messages in English. UI text in Polish.
- One stage = one thread = one pull request. Run tests and linters before opening a PR.
- When a decision changes, update `docs/spec.md` (and `docs/plan.md`) first, then the code.
- Do not add technology outside the stack below without asking.
- Secrets only in environment variables (`.env` is git-ignored, `.env.example` is committed).
- If something is unclear, make a reasonable assumption, write it in the PR description, and continue.
- Keep this file current when commands or conventions change.

## Stack

- Backend (`backend/`): Python 3.13, Django + Django Ninja (OpenAPI), PostgreSQL 16, Django sessions, dependencies managed with `uv`.
- Background jobs: Procrastinate on Postgres (no Redis). Worker = `manage.py procrastinate worker`, same code as the API.
  Save data and defer the job in one `transaction.atomic()` block.
- Scheduling engine (`backend/engine/`): pure Python, must not import Django. OR-Tools CP-SAT runs only in the worker.
- Frontend (`frontend/`): TypeScript, React + Vite SPA, TanStack Router (file routes in `src/routes`) + TanStack Query,
  Tailwind CSS v4 (+ shadcn/ui from stage 6), React Hook Form + Zod, dnd-kit. API client generated by orval.
- Docker Compose: `db`, `api` (gunicorn), `worker`, `caddy` (serves the SPA, proxies `/api`, serves Django static files).
- LLM (stage 10): Claude via the Anthropic Python SDK, key only from `ANTHROPIC_API_KEY`.

## Commands

Everything at once (http://localhost:8080):

```bash
cp .env.example .env        # once
docker compose up --build
```

Backend outside Docker (needs Postgres, e.g. `docker compose up -d db`):

```bash
cd backend
uv sync
uv run python manage.py migrate
DJANGO_DEBUG=1 uv run python manage.py runserver          # API on :8000
DJANGO_DEBUG=1 uv run python manage.py procrastinate worker
uv run pytest                                             # tests (need Postgres)
uv run ruff check . && uv run ruff format --check .       # lint
uv run python manage.py makemigrations --check --dry-run
```

Frontend (dev server on :5173 proxies `/api` to :8000):

```bash
cd frontend
npm install
npm run dev
npm run lint && npm run typecheck && npm test && npm run build
```

After changing the API, regenerate the schema and the client (CI fails if they are stale):

```bash
cd backend && uv run python manage.py export_openapi_schema --api config.api.api --indent 2 --output ../frontend/openapi.json
cd ../frontend && npm run api:generate
```

## Conventions

- API lives under `/api`; every endpoint is in a router of its app (`apps/<app>/api.py`) and added in `config/api.py`.
  OpenAPI operation id = view function name, so name views as the frontend hook should read (`health` → `useHealth`).
- Tenant isolation (from stage 2): every company-owned table has `company_id`; API code reads data only through
  the tenant context / `for_company()` querysets. Each new endpoint gets a cross-company access test.
- Background tasks live in `apps/<app>/tasks.py` (auto-discovered). Solver jobs go to queue `solver`, the rest to `default`.
- Do not edit generated files: `frontend/src/api/generated/**`, `frontend/src/routeTree.gen.ts`.
- Frontend calls the API only through the generated hooks; `src/api/http.ts` adds the session cookie and CSRF token.
- Every screen has an empty, loading and error state with plain-language Polish text.
- Visual tokens (stage 6) are the only source of colours, type, spacing and radii. No purple gradients, glass, emoji icons.
- Tests: `backend/tests/` (pytest + pytest-django, real Postgres), frontend tests next to components (`*.test.tsx`, Vitest).
